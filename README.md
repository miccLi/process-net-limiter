**ProcessNetLimiter** 是一个轻量级、现代化的 Windows 桌面应用程序。能够实时枚举系统中所有正在运行的程序，智能将**游戏、网盘、下载器**优先置顶，支持多选并自由限制上传与下载速度（提供 `完全断开连接`、`1 KB/s`、`100 KB/s`、`1000 KB/s` 及 `自定义限速`），且支持上传和下载独立配置与一键解除所有限制。

---

## ✨ 核心特性

- 🎯 **智能分类与优先置顶**：
  - 自动识别并分类：⚡ 下载器（迅雷、IDM、qBittorrent等）、☁️ 网盘（OneDrive、百度网盘、阿里云盘等）、🎮 游戏（Steam、Epic、原神、CS2等）、🌐 浏览器与通讯。
  - 排序优先级：已限速程序 > 下载器 > 网盘 > 游戏 > 活跃网络连接程序 > 普通后台进程。
- 🚀 **灵活速度限制档位**：
  - **完全断开连接 (0 KB/s)**：一键彻底阻断目标程序的网络通信。
  - **1 KB/s**：极速限制，适合断流测试或后台静默。
  - **100 KB/s**：低速限制，保留基本心跳包与连接，不占带宽。
  - **1000 KB/s**：约 1 MB/s 中速限制，在后台下载的同时确保前台浏览和游戏毫无延迟。
  - **自定义速度限制**：支持自由输入任意数值与单位（KB/s、MB/s）。
- ⚙️ **上传与下载独立控制**：
  - 既支持“上传下载联动设置”，也支持分别独立配置上传速度与下载速度。
- ⚡ **一键解除全部限制**：
  - 一键扫描并清空所有由本工具下发的 QoS 限速策略与断网规则，恢复全局正常网络。
- 🛡️ **原生 Windows QoS + 高级防火墙机制**：
  - 无需安装第三方不稳定驱动或未签名驱动，不报毒，不导致蓝屏，随用随关。
- 🎨 **极简深色现代化 UI**：
  - 基于 PyQt5 打造的现代化深色质感界面，支持多选、实时搜索与高分屏缩放。

## 💡 常见疑问科普：入站/出站规则 vs 上传/下载速度？

> **问：高级安全 Windows 防火墙中的“入站规则”和“出站规则”，是不是和“上传”与“下载”是一个意思？**

**答案：并不是完全等同的，两者在网络协议分层中属于不同的概念。**

1. **出站 (Outbound) vs 入站 (Inbound)**：
   - 关注的是**连接是由谁发起的（连接发起方）**。
   - **出站连接 (Outbound)**：由**本机进程主动向外发起的连接**。例如你在浏览器打开网页、在迅雷/网盘中下载文件、在 Steam 中更新游戏，这些连接全部都是由本机主动向外部服务器发起的，因此在防火墙判定中都属于**出站 (Outbound)**！
   - **入站连接 (Inbound)**：由**外部设备主动向本机监听的端口发起的连接**。例如本机构建了 Web 网站、局域网共享服务器或 Minecraft 联机房间，外部玩家连接进来，才属于入站连接。
   - **为什么不能简单用防火墙限速？** 因为防火墙主要负责“放行”或“丢弃/阻断”数据包，不具备平滑的流量整形（Rate Limiting）功能。
2. **上传 (Upload) vs 下载 (Download)**：
   - 关注的是**数据流的传输方向**。
   - **上传速度**：本机对外发送应用层数据的速率。Windows 原生 QoS 机制可以直接限制进程的出站发送字节速率（`ThrottleRateActionBitsPerSecond`）。
   - **下载速度**：外界向本机发送应用层数据的速率。在 TCP 协议机制中，由于接收端（本机）必须向服务端持续回传确认包（TCP ACK / Window Update）才能推进传输窗口，通过 QoS 策略精确限制这些出站反馈流的节奏，即可从协议层优雅地让对端服务器按预设速率（如 100 KB/s）向本机推送数据，从而平滑实现下载限速。
   - **完全断开连接**：此时则通过 Windows 防火墙直接阻断该程序的所有出入站流量，实现 100% 毫秒级断网。

## 🛠️ 安装与运行

### 依赖环境
- Windows 10 / Windows 11
- Python 3.10 或更高版本

### 安装步骤
1. 克隆代码仓库：
   ```bash
   git clone https://github.com/miccLi/process-net-limiter.git
   cd process-net-limiter
   ```
2. 安装所需依赖：
   ```bash
   pip install -r requirements.txt
   ```
3. 启动程序：
   - **推荐方式**：双击运行 `run.bat`（会自动检测并请求管理员权限以确保 QoS 规则正常下发）。
   - **命令运行**：右键以管理员身份打开 PowerShell/CMD，运行：
     ```bash
     python main.py
     ```

## 📖 使用指南

1. **刷新与筛选**：打开程序后，所有正在运行的进程会自动分类呈现，游戏、网盘和下载器会自动置顶。
2. **勾选程序**：在表格左侧勾选一个或多个想要限速的目标进程（支持点击行快速选中）。
3. **选择限速档位**：
   - 在底部下拉框中选择预设限速（1 KB/s、100 KB/s、1000 KB/s、完全断网或自定义）。
   - 如需分别设置，勾选“分别设置上传和下载速度”。
4. **应用限速**：点击 `🚀 应用限速`，规则将在 1 秒内生效。
5. **解除限制**：
   - 勾选程序后点击 `❌ 取消选中限制`；
   - 或随时点击 `⚡ 一键解除全部限制` 恢复初始网络状态。

## 🔍 深度技术剖析：为什么 Steam 等软件限制单个 exe 不够？为什么下载限速表现不同？

### 1. 现代软件的多进程架构（父子进程与下载引擎）
现代大型软件早已不再是单一进程模式：
- **Steam**：`steam.exe` 本身仅作为客户端主框架和登录通道（连接 27024 等控制端口）；而海量游戏数据分发（CDN 流量）是由其内部的 **`steamwebhelper.exe`** 以及 `steamservice.exe` 通过并发 HTTP/HTTPS (443端口) 甚至 WebSocket / QUIC 协议直接拉取的。
- **网盘与下载器**：百度网盘的实际下载由 `baidunetdiskhost.exe` 承担；迅雷由 `downloadsdkserver.exe` 承担。
- **本工具解决方案**：已内置**进程家族智能联动引擎 (Associated Processes Engine)**。当您选中限制或阻断 `steam.exe` 时，工具会自动将其关联的所有核心下载与工作子进程（`steamwebhelper.exe`、`steamservice.exe` 等）**全部一并下发策略**！

### 2. Windows 原生 QoS 机制的真实机理（上传 vs 下载）
- **上传限速 (Upload)**：Windows 原生 QoS (`New-NetQosPolicy`) 属于内核级出站流量整形（Egress Shaper），能对指定进程发送向外的字节流实施硬性封顶，表现极为稳定强劲。
- **完全断开连接 (Block)**：联动 Windows 高级安全防火墙出入站双向规则，实现 100% 毫秒级彻底阻断。
- **下载限速 (Download)**：
  - Windows 原生系统并不提供类似 Linux `tc ingress` 的用户态原生“下行字节硬性截流队列”（商业软件如 NetLimiter 是通过安装自研的底层 NDIS / WFP 内核驱动 `nlwfp.sys` 在驱动层强行丢包截断）。
  - 在纯 Windows 原生无第三方驱动环境下，本工具通过 QoS 精确限制出站流与 TCP ACK 反馈节奏，促使常规单连接 TCP 服务端自动降速。但若应用使用多线程并发 CDN、或者您开启了 **TUN 虚拟网卡 / 游戏加速器 / 代理工具**（流量被虚拟网卡拦截转送），下行数据包可能会绕过物理网卡的 QoS 整形。
  - **测试与断网建议**：若想彻底阻止某应用占用网络或进行断流测试，强烈推荐选择 **`完全断开连接 (0 KB/s)`**，此模式下无论 CDN 还是多进程均会瞬间被防火墙彻底阻断！
